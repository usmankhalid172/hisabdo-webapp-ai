## 1. Principle

The assistant states a HisabDo fact only when an approved, verified KB passage says it. It names a source only when
that source supports the sentence it is attached to. When the documentation is silent, ambiguous or self-contradictory,
it says so plainly and politely. The prompt asks the model for this, and code enforces it after the model replies.

## 2. Pipeline

```
message ─► input guardrails ─► R1/R10 clarify? (topic-less or expense-only) ──yes──► one clarifying question
                │ no
                ▼
         third-party guard ─► intent router ─► own figures / entries: other routes (no KB text)
                │ knowledge / general
                ▼
         retrieve (hybrid, threshold 0.566273, top 2) ─► R4 relevance gate + R4b rare-word gate
                │ nothing left ─► R2 fallback (no_source / out_of_scope)
                ▼
         conflict group?  ─► R11 resolve (deterministic) or R3 show every version
                │ no
                ▼
         English + real model: GROUNDING_RULES + numbered sources ─► draft ─► R4 sentence check + R12 link check
         mock model or Urdu / Roman Urdu: source text quoted (R7)
                ▼
         R12 citation audit (every reply) ─► R5 Sources list ─► output guardrails ─► user
```

## 3. System prompt alignment

| Layer | Text | Role |
|---|---|---|
| `SYSTEM_PROMPT` (all routes) | Rules 3, 3a, 3b: never invent product details, UI steps or figures; context is the complete set of allowed facts; ask one clarifying question when ambiguous | Persona and general limits |
| **`GROUNDING_RULES`** (knowledge route, updated 12 Nov) | See below | Tells the model exactly what R4, R3, R1 and R12 will enforce |

```text
Answer ONLY from the numbered sources below. They are HisabDo's verified documentation.
- After each fact, cite the source that states it as [n]. Cite a source only if it states that fact.
- Do not add facts, steps, button names, links, page names or numbers that the sources do not contain.
- Do not write links or source titles yourself; they are added below your answer from the sources you cite.
- If the sources do not answer the question, say you could not find it in HisabDo's official help pages and
  suggest contacting HisabDo support at hisabdo.app@gmail.com. Do not guess.
- If two sources disagree, say so, give both with their source numbers, and do not choose one.
- If the question could mean more than one thing, ask one short clarifying question instead of answering.
- A source marked "legal page" is quoted with its section, never turned into advice.
- Do not list the sources yourself; they are added below your answer.
```

Each source block given to the model carries its number, page title › section, link, kind (help page / legal page)
and page date. Links and titles shown to the user are always rebuilt from the KB record, never taken from the
model's text.

## 4. Response rules

| Rule | Rule | Enforced by |
|---|---|---|
| R1 Clarify first | A message with no topic ("how?", "kaise?") gets one open question listing the main areas. A one-word topic matching two different sections gets "Do you mean A or B?". Runs **before** routing and the off-topic guard (new), so "how?" is no longer refused | `pre_clarify`, `clarify` |
| **R10 Ambiguous expense question** (new) | A message whose only topic is expenses ("expenses", "kharcha", "my expenses?", "خرچہ") gets one question: add an expense, see totals, or learn how expense tracking works. In English, Roman Urdu or Urdu. Previously "expenses" got a refusal and "kharcha" started an entry ("Kitne paise the?") | `pre_clarify`, `service._guarded_chat` |
| R2 No source, no facts | Nothing relevant → "I couldn't find this in HisabDo's official help pages, so I won't guess", plus the support email and Contact page (from the KB), and how to rephrase. Tax, legal and investment questions add "consult a qualified accountant" | `fallback` |
| R3 Conflicts shown | Unresolvable disagreement: every version, with its source and date, no chosen answer, `needs_review: true`, `kb_conflict` log (ids only) | `conflict` |
| **R11 Deterministic conflict resolution** (new) | Versions are ordered by source authority (FAQ 1 > feature page 2 > legal 3 > general guide 4), then by id, so the order never varies. **Resolved** only when one version is both the most authoritative **and** the only one carrying the newest page date. The reply then leads with it and still shows the others ("Another source says…"), with `needs_review: true` and reason `resolved: …`. In every other case, R3 applies. Undated pages are never treated as newer | `resolve`, `conflict` |
| R4 Cite only what supports | A passage is used only if it covers at least ⅓ of the question's topic words. Every sentence of a model draft must share at least 50% of its content words with the cited passage. A better source (+0.2) replaces a weak one. Unsupported sentences are dropped. If nothing is left, R2 applies | `relevant`, `verify`, `support` |
| **R4b Rare-word gate** (new) | A passage from a neighbouring help topic (its heading does not name what was asked) must contain at least one of the question's rare words (in ≤ 10 KB passages). Example: "connect to my bank account" was answered from the sign-in page because the two only shared "account" | `_answer` (`RARE_DF`) |
| R5 Show sources | Every KB reply ends with `Sources:` and `[n] Page title › Section: link` for cited passages only. The same data goes in `citations[]` | `_with_sources` |
| R6 Legal pages quoted | Privacy, Terms and Disclaimer text is quoted with its section and link, never paraphrased into advice | `extractive` |
| R7 Language | The frame is in the user's language and script. The evidence is the English source text, quoted verbatim | `TEMPLATES` |
| R8 Neighbouring topic | When the passage answers a nearby question, its leading "Yes"/"No" is dropped and the reply names the help topic it comes from | `extractive` |
| R9 One source unless needed | A second source is cited only when it covers what the first leaves open | `extractive` |
| **R12 Citation audit** (new, every reply) | (a) Every citation must be a KB passage, with **that passage's** link and title. (b) Its `[n]` must appear in the reply, so no unused sources are listed. (c) Every `[n]` must point to a listed source. (d) Links that do not belong to a cited source are removed; the official Contact page is the only exception. (e) In a model draft, a sentence that carries an invented link is dropped entirely. (f) If no valid citation is left, R2 applies | `audit`, `verify` |

## 5. Fallback wording (respectful and safe)

| Case | Reply (English; Roman Urdu and Urdu versions in `TEMPLATES`) |
|---|---|
| No documentation | "I couldn't find this in HisabDo's official help pages, so I won't guess. You can ask HisabDo support at hisabdo.app@gmail.com or through the Contact page (https://hisabdo.app/contact); they aim to reply within 48 hours. You can also rephrase the question or ask about a specific feature, such as PDF reports, backup or customer udhar." |
| Outside the knowledge route | "I can help with HisabDo and with bookkeeping for your business, but I don't have reliable information on that…" |
| Tax / legal / investment | Fallback + "For advice specific to your business, please consult a qualified accountant." |
| Unresolved conflict | "HisabDo's official sources don't agree on this yet, so I can't give you one answer. I've flagged it for review." + every version |
| Ambiguous expense question | "Do you want to add an expense, see your expense totals, or learn how expense tracking works in HisabDo?" |

The wording never blames the user, never guesses, and never states a product fact without a source. The only facts
it states (support email, Contact page, 48 hours) come from the KB itself.

Bugs the transcripts exposed and this change fixed:
1. An invented link was cut out, but its sentence ("Download it at") stayed with a citation. Now the whole sentence is dropped.
2. "kharcha" started an expense entry. "how?" and "kaise?" were refused as off-topic.
3. "How do I export my expenses to Excel?" was sent to the account-figures route and showed the demo balance (D3-10). How-to questions are now excluded from that route when grounded answers are on.
4. The bank-connection question was answered from the sign-in FAQ (D3-26).

## 8. Limits

* The live KB has one conflict group (currencies, C-06) and its pages carry no dates. R11 therefore leaves it
  unresolved, which is correct. Resolution is shown on synthetic dates only.
* R4b uses word frequency. A question whose only rare word is a synonym the KB does not use falls back to R2, which
  is safe but may lose an answer.
* The three remaining held-out wrong citations (2 Urdu script, 1 khata) are retrieval misses (D3-25, D3-31), not
  rule failures.
* The 26 failures in `tests/xictek_website_assistant` already happen without these changes, in a separate module.
